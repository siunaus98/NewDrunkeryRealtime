# 设施上限与料理区容量

初始备料桌为3张（TestTable、PrepTableA、PrepTableB），商店最多额外购买3张，最终合计6张。堆叠台最多3个、履带10个、明光灯2个、弩台10个；其余上限保持现有值。摇摇车与传送门按购买一对计算两个端点。弩台、捕兽夹和铲车购买后交付至近门战斗区，不计入料理区设施总占地。

两个明光灯的工作效率增益按加法叠加：1 + 22% + 22% = 1.44倍，作用于料理台、酒桶、净化池、培养皿及已有使用工作光环的运输设施。离开范围、隐藏或搬起灯后撤销对应增益。商店继续仅显示简短用途，不添加效果数值；图鉴同步购买上限及叠加规则。

料理区尺寸2304×1280，每格128×128，即18×10=180格。按设施声明的格子占地计算（设施可重新整理，空格包括行走和操作区域）：

上菜桌位于料理区边界外，商人位于料理区外，均不计入。铲车在战斗区交付；以上预算也不计玩家主动驾驶铲车进入厨房的临时占地。BOSS专属食材沿用搬回的掉落物，不另建食材箱。

传送门还各需保留1格出口，额外2格不适合摆放其他设施。因此扣除出口后，余下可安排空间为**97格（53.89%）**。该结果表示空间总量，不保证随意摆放后仍然连通；空格还需承担走路、设施操作及布局调整用途。未来新增当前12种之外的食材箱，需要继续从这份余量中扣除。

## 验证

`tools/validate_facility_capacity.gd` 读取真实地图和初始场景逐项核算；检查初始桌数量、商店上限、双灯相加、离开范围/隐藏/搬起灯后的撤销；启用全部食材箱后，通过真实商店交易逐项买到上限，验证售罄隐藏和旧卡片不能突破上限，并检查战斗设施交付区域。计算结果写入`_artifact_work/kitchen_capacity.json`。
