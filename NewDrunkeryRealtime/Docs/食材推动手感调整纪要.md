# 食材推动手感调整纪要

本文档记录 2026-05-09 这轮围绕料理区食材推动手感的调整结论，用于后续快速恢复上下文。

## 1. 本轮目标

- 修复仓库 / 食材的贴脸交互问题。
- 修复玩家推动食材时的“卡顿、瞬移、穿模”手感问题。
- 修复玩家放下食材后偶发卡死的问题。
- 尽量保留原本的视觉与玩法效果，不额外扩大改动范围。

## 2. 最终达成的手感结论

当前已经确认可接受的结果是：

- 普通走路推物正常。
- 纵向冲刺推物正常。
- 横向冲刺推物正常。
- 横向从远处冲刺时的空气感已经明显减少。
- 移动中起手冲刺不再容易被食材直接掐断。
- 放下食材后不再立刻长期卡住玩家。

当前用户反馈认为：

- 整体已经达到预期的约 90%。
- 剩下的 10% 未必合理，因此先不继续追。

## 3. 已知稳定方向

### 3.1 玩家与食材的交互分工

- 玩家身体实体碰撞与推物判定不能混成一个东西。
- 平时移动、拾取、放下，依赖基础判定。
- 冲刺推动允许使用更强的推物语义，但不能改坏玩家常态体积。

### 3.2 推动物体的基本原则

- 食材不能在玩家还没真正接触时就被提前推出明显空档。
- 食材不能在刚被顶动后立刻重新变成硬墙，把冲刺掐断。
- 多个食材堆叠时，后一个应尽量继承前一个的实际位移，而不是各自独立补位。

### 3.3 放下食材的原则

- 食材应尽量贴着玩家放下。
- 若真发生重叠，允许短暂兜底解卡。
- 放下后的食材不应因为兜底逻辑而把玩家长期锁死。

## 4. 当前实现要点

当前相关逻辑主要集中在：

- [RealtimePlayer.gd](D:/P-ND/NP/NewDrunkeryRealtime/Scripts/Player/RealtimePlayer.gd)
- [LooseItem.gd](D:/P-ND/NP/NewDrunkeryRealtime/Scripts/Kitchen/LooseItem.gd)

### 4.1 玩家侧

- 推物逻辑使用了队列式传播，不再只看单个食材。
- 冲刺时会启用更强的推物参数。
- 已加入“临时忽略特定食材”的机制，用来处理：
  - 刚放下的食材
  - 冲刺起手时已经贴住的食材
- 推物判定和放下判定不再把玩家常态体积替换成奇怪的动态几何。

### 4.2 食材侧

- 地面食材继续保留推开、旋转、减速、拾取等基础表现。
- 食材之间仍保留轻量分离，避免完全重叠。
- 冲刺和普通移动的差异，主要由玩家侧推动逻辑控制。

## 5. 本轮最终共识

- 不继续追求“冲刺必然把食材强行拉开很远”的极端表现。
- 不继续扩大玩家判定体积的动态变化。
- 先保留当前 90% 的手感结果，后续若要再调，只针对明确合理的新需求。

## 7. 后续已知问题：推行抽搐

2026-06-20 反馈：玩家移动时如果持续推着食材走，食材偶尔会出现轻微抽搐式位移。当前不影响玩法，但会削弱成品观感，后续需要专门处理。

初步判断风险点：

- 玩家侧会在同一物理帧内执行主动推物、轴分离移动、二次推物与边界钳制。
- 食材侧同时保留自身 `move_and_slide()`、速度拖拽、重叠分离、链式推物与边界钳制。
- 当玩家持续压着食材移动时，食材可能在“玩家主动分离”和“食材自身碰撞 / 重叠修正”之间来回被修正，从视觉上表现为抖动。

后续建议单独开一轮小步验证，不要顺手改：

- 先增加仅开发期可开启的推物调试信息，观察同一帧内食材被移动的来源。
- 优先尝试让被玩家直接推到的食材在该帧跳过自身重叠分离，或合并玩家推物与食材自身位移的职责。
- 每次只改一个变量或一个阶段，并保留冲刺、放下、多个食材堆叠三类回归测试。
