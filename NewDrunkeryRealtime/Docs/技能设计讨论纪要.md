# 技能设计讨论纪要

日期：2026-05-20

## 讨论前提

- 技能的目标是帮助通关，不直接等同于基础战斗力。
- 技能本体应尽量简单，遗物与祝福负责在其上继续加法。
- Demo 计划包含三名初始角色，角色差异应先体现在流程职能上，再落实到技能与大招。
- 派生不应只是数值变化，而应是同根但职责明显分叉的变体。

## 已达成共识

- 池饱饱适合走“运势/转机”方向，允许高波动、高惊喜的构筑。
- 梵倪拉的神权应围绕美食、美酒、宴饮、熟成与赐宴展开，不应偏向时间系。
- 纳芙蒂蒂应是会战斗、会护人、会稳场的猎手型角色，不应只做后勤。
- 三名角色的差异重点应落在“她们是怎么解决问题的人”。

## 当前角色方向

### 池饱饱

- 倾向：转机型、运势型。
- 关键词：加速、后厨转场、随机收益、上菜后回报。
- 初始遗物讨论：
  - `灶神骰`：上菜后掷骰获取随机收益。
  - `家常围裙`：更稳定的流程衔接型遗物，适合对冲赌狗流。

### 梵倪拉

- 倾向：改规则型、宴饮神权型。
- 关键词：赐酿、醉意、入味、神宴、后厨爆发、战场干扰。
- 设计关注点：
  - 技能应体现“让对象进入宴饮规则”。
  - 派生应明确分成偏战斗 / 偏后厨两个方向。

### 纳芙蒂蒂

- 倾向：稳场猎手型、战斗护卫型。
- 关键词：猎步、标记、回收、护驾、猎场、稳住局面。
- 设计关注点：
  - 技能必须有明确战斗动作。
  - 派生应分别偏向主动狩猎与守护场地。

## 仍待确定

- 每个角色最终采用的技能基底与派生数量。
- 三名角色的初始遗物最终二选一方案。
- 池饱饱的随机流派到底保留多大波动幅度。
- 梵倪拉与纳芙蒂蒂的具体技能名称与视觉表现。

## 早期 Godot 原型实装备注（已被新方案取代）

本节用于避免“设计方向”和“当前工程状态”混淆。

当前已经实装：

- 游戏初始界面与开局选择界面已经有第一版。
- 当前只开放 `池饱饱`，`梵倪拉` 与 `纳芙蒂蒂` 只是 UI 占位。
- 开局界面已经展示：
  - 小技能三选一
  - 大招三选一
  - 初始遗物二选一
- 当前选择结果会通过 `run_setup` 传入主场景，并写到玩家 meta 上。
- `PlayerSkillController.gd` 已接入玩家，当前可用按键为：
  - `U`：小技能
  - `I`：大招
- 当前小技能实装效果：
  - 短时间移动速度提升
  - 3 秒内持续提供料理加工效率加成
  - 测试半成品加工台使用 100 点连续加工进度：切菜基础 6 次完成，小技能期间每次约推进 25%，约 4 次完成；煮 / 炒也会按时间进度吃到同类效率加成
  - 自动煮锅完成后会进入过火进度，过火后食材变黑并成为坏掉状态
- 当前大招实装效果：
  - 限时强化料理窗口
  - 接下来的若干次加工可以瞬间完成
- 技能冷却与 buff 状态已经有基础 UI 表现。

当前尚未完成：

- 开局选择中的三个小技能 / 三个大招还没有全部形成不同实战效果。
- 初始遗物选择目前主要是 UI 与数据骨架，尚未完整接入实际遗物效果。
- `灶神骰`、`家常围裙` 等遗物仍处于设计方向 / 文案占位阶段；开局界面当前只记录选择，并在卡片上说明后续预期效果。
- 当前技能原型更接近“验证技能输入、冷却、料理加成链路”，不代表最终池饱饱技能定稿。
- 祝福池当前只有三项测试数值强化，不代表最终祝福设计质量。

当前判断：

- 现阶段应把技能系统视为“最小可用骨架已接通”。
- 下一步若继续推进角色差异，应优先让开局选择真正影响技能效果，而不是继续只扩 UI 卡片数量。
