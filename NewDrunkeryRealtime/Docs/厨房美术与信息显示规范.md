# 厨房美术与信息显示规范

2026-11-14 的材质、环境与界面统一规则见 [美术统一优化记录](美术统一优化_2026-11-14.md)。后续生成 SVG 后需执行 `python tools/finish_art_direction.py`，保留本轮的统一材质；加工状态图标继续使用其原有语义色。

## 当前基准

厨房设施以 `ArtResource/Kitchen/plate_wash_station.svg` 和 `trash_bin.svg` 为基准：暖木色、大色块、清晰深色轮廓、少量高光，阴影克制。不要添加写实纹理、复杂投影或不透明的地面背景。

- 轮廓：`#513420`，深部：`#754829`。
- 木面：`#edb86a`、`#d79550`；柜体：`#a96638`、`#ca8a50`。
- 高光：`#ffdc94`、`#f5cb82`；金属配件：`#f3cc7c`。
- 色块和轮廓在正常镜头下可读，装饰不得与可交互物品混淆。

桌子使用开放桌腿和留白台面；组合台使用连续操作面和抽屉；上菜口使用简洁服务垫。不要在贴图内画固定食材、成品盘子或假订单槽位，它们应由真实状态显示。

当前桌子、组合台、上菜口、切 / 磨 / 烤台、食材箱、盘子组、垃圾桶与酒桶统一采用更俯视的角度，扩大上表面、收短正面立面。旧设施保留 1024 × 1024 透明画布以兼容分层精灵和搬运取样；更改的是画布内部造型，不能通过单纯纵向拉伸把食材压扁。

桌子、切 / 磨 / 烤台和组合台上的物品统一为 128 像素画布 × 0.56 世界缩放，与玩家手持物相同；设施自身缩放在物品层得到补偿。组合台放大为三格宽、两格深，六份食材按三列两行排列，绘制与定向拾取共用同一位置计算。组合台默认隐藏交互调试网格。上菜口扩大台面后同步扩大其碰撞深度，以免出现视觉台面可穿过的情况，保留原有外侧布局与窗口编号。

食材、料理、酒水及所有实际出场敌人使用同一深木色轮廓、少量平涂与高光。食材保留品类外形；成品区分卷、饼、串、炖锅、甜品和拼盘，避免统一使用生料叠盘的造型。敌人保留动物剪影与可辨认的角、耳、翅膀、钳、尾部等特征。

`tools/generate_cohesive_art.py`、`cohesive_menu_art.py` 与 `cohesive_enemy_art.py` 可重建本轮 SVG。料理部分从 `TestItemDefs.gd` 读取配方组件，运行时配方仍只维护在该数据表中。生成器用于美术离线维护，不参与运行时逻辑。

### 同类素材的辨识要求

- 晴天梅使用黄绿色、圆润小果、果缝和短果梗，避免苹果式双瓣凹口及大红果身。
- 同类菜品不能只换一个小装饰：饼类区分小圆饼、三角禽饼、夹层烤饼和籽脆片；卷类区分叶包、切段面卷、菜卷切面和折叠菜包；甜品区分粉色甜羹、双色酿冻、烤盅与拼盘。酒水同时区分杯型、酒色及装饰。特殊造型维护在离线的 `cohesive_menu_art.py` 中，不复制或修改配方。
- 敌人使用食材联想色与清晰主色：红鬃羊玫红、沙原禽浅色羽身与灰蓝翅、沙兔杏粉、驼紫、芽甲虫青绿、狙击甲虫蓝、蛾金黄与珊瑚色、刺球叶绿、守卫青蓝与金黄；蝎子偏紫红、秃鹫蓝灰与紫色。机制偷料甲虫保留琥珀金，沙虫保留土金。不要强求现实动物配色。
- 酒桶是横置圆弧木桶，具有桶箍、可见端面和龙头。中央显示 64 像素酒种图标，右下大号数字显示可取份数；空桶无图标，酿造中提前显示当前酒种并保留中性加工进度条。库存不再使用酒色填充条表示。
- SVG 在编辑器导入时栅格化为纹理；运行时使用缓存纹理，不调用 Python 或逐帧重新解析 SVG。酒桶只在状态变化或实际酿造时请求重绘，闲置时复用已有绘制命令。

## 玩家手持信息

- 半成品：玩家头顶显示加工图标；小料盒同时显示原食材身份。
- 运输盘：头顶气泡逐份展示实际内容与加工状态，最多六份；重复食材不合并。装入、取出和倒空时立即刷新。
- 完成菜品：头顶先显示菜品图标，再逐份展示全部实际食材，包含切加工与酒水组件，加工图标显示对应实际状态。最多六份食材加一个菜品图标，不增加展开键。读取制作时保存的签名，不用默认配方代替实际内容或熟成度。
- 空盘、脏盘隐藏内容气泡。没有实际制作签名的成品只显示菜品图标，不虚构配方；单独酒水亦显示自身图标。

物品本体不再额外悬浮加工图标，包括桌面、地面和手持物，避免重复提示。保留原有食物色泽和切痕等本体特征。加工过程中的烤台进度图标和玩家磨料进度图标仍然保留。

## 小料盒

放大盒面上的原食材图案，以食材身份而非通用容器作为主要辨认依据。下方剩余份数使用大号白字和深色描边。粗磨盒使用棕色状态角标与大颗粒图标，细磨盒使用黑色状态角标与细颗粒图标，复用订单 / 气泡的研磨图标；盒底保留对应色带，在正常镜头下辅助区分。角标贴在盒面上，不额外悬浮在盒子上方。状态读取 `payload.process_state`，不要用美术表现推断或修改加工数据。

## 盘子组数量显示

盘子架与净化池不再常驻显示名称或“净盘 / 脏盘”文字。左侧盘子架下方仅显示干净盘数量，右侧净化池下方仅显示脏盘数量，零库存显示 `0`。两侧数字同高，使用 32 号白字与深色描边，随拿取、归还、放入、清洗和重置即时刷新。按键交互提示保留。

## 菜品容器与装盘分层（2026-10-20）

料理图标与世界中的容器分开处理。`TestItemDefs.get_item_texture()` 始终返回用于图鉴、订单和 UI 的食物本体图标；世界显示通过 `get_world_item_texture(item_id, payload, fallback)` 按状态选择素材：

- 组合台刚制作完成的非酒水料理显示未装盘的食物本体；汤羹显示制作容器。
- 玩家使用干净盘子取走后，`payload.uses_plate` 设为 `true`，手持、桌面、地面和搬运残影统一显示装盘版本。
- 已装盘料理再次放上组合台不会去掉盘子，也不会额外消耗盘子；盘子内卸载食材仍按原有规则处理。
- 失败料理同样遵守装盘分层；垃圾桶 / 地面可处理失败料理，组合台不把垃圾重新当作组件接收。
- 酒水属于自带杯具的组合组件，不因 `uses_plate` 获得额外餐盘。

离线生成器 `tools/generate_cohesive_art.py` 维护 `ArtResource/Generated/Dish`、`DishPrepared` 和 `DishPlated` 三层素材。运行时不解析 SVG，也不改变配方、料理签名或盘子容量。专项验证为 `tools/validate_dish_presentation.gd`，覆盖空手取餐限制、汤羹制作容器、装盘后的跨桌面 / 组合台 / 地面搬运、失败料理、酒水和料理签名保留。

### 切台与研磨台辨识规范（2026-10-20）

切台与研磨台不再共用相似的浅色平面轮廓：切台使用浅木砧板、横向木纹和明显的厨刀；研磨台使用深青灰石台面、较大的研钵与竖向杵棒。两者的碰撞、加工参数、物品层和交互逻辑保持不变，仅替换离线生成的设施贴图。
