# 美术统一优化 · 第一轮

以现有盘子组、垃圾桶的暖木色、深色轮廓和克制高光为设施基准；以池饱饱为画面细节的参照；借鉴沙灵的分层光效改善动作反馈。玩家原始立绘保持原样。

## 本轮范围

- 165 个 SVG 统一材质明暗和高光。其中食材、敌人、设施增加对应的表面细节，菜品保留各自轮廓、摆盘和容器层次。不是所有素材都重新设计剪影。
- 夜间 NPC 补充服装、面部和饰物细节；女神像和商人改为同一套圆润轮廓与石材、布料配色。
- 料理区使用对齐摆放格的砂岩地砖；战斗区使用细沙纹理；沙丘增加分层轮廓；传送点改为嵌入式符文石。地形边界、碰撞和路牌位置不变。
- 标题、准备、图鉴、选项、事件对话、结算和 HUD 统一为深青绿面板、金色边框和浅米色文字。技能栏增加独立图形，并整理图形、状态、费用与按键的位置。
- 普通敌人增加轻微待机和移动起伏，避开攻击与受击动画；攻击增加方向光弧，命中增加短暂火花；弹道、流沙、风暴与增益圈增加少量装饰粒子。
- 加工时增加蒸汽或碎屑；洗盘时增加水花。特效只读取工作状态，不推进工作。
- 屏外 NPC 卡片避开右侧资源栏及底部技能栏，访客到来提示改为两行。

## 必须保留的信息规则

- 熟成度与加工方式的语义色不参与材质调色：微生黄、半熟橙、全熟红、快糊褐；粗磨棕、细磨黑、切白。
- BOSS 特殊客人的红色订单、精英客人的金色标识、生命条的绿黄橙红区分继续保留。
- 玩家头顶气泡继续显示盘子或菜品的组件和加工状态；半成品不额外增加常驻熟成度浮标。
- 盘子、未装盘料理与已装盘料理继续按真实物品状态选择贴图。
- 显示层不能改变移动、攻击判定、设施占地、订单、随机种子或收益。

## 维护入口

静态素材继续使用 SVG，导入时由 Godot 生成纹理。运行中不会反复解析 SVG，也没有为本轮材质增加实时模糊或全屏后处理。

生成任意素材后执行：

```powershell
python tools/finish_art_direction.py
```

该脚本只依赖 Python 标准库，重复执行会替换已有材质定义，不会叠加；跳过 `Generated/Process` 的加工状态图标。原始平涂色保存在 SVG 的 `data-base-fill` 中。组合素材中的旧材质定义也会清理，防止渐变 ID 冲突。

`generate_cohesive_art.py` 和 `generate_event_art.py` 已接入材质处理。`generate_facility_art.ps1` 等其他生成器运行后，仍应执行上面的最终处理。需要重画现有定制素材时，先检查对应源生成器是否覆盖了该素材，不要为修改单个素材盲目重建整个目录。

女神像和商人由 `tools/generate_landmark_art.py` 维护；先生成事件素材，再生成这两个地标。

运行时表现入口：

| 范围 | 文件 |
| --- | --- |
| 地面、沙丘与传送点 | `Scripts/Core/WorldSurfaceArt.gd` |
| 面板公共风格 | `Scripts/UI/AtelierStyle.gd` |
| 敌人轻量动画与影子 | `Scripts/Enemies/EnemyPresentation.gd` |
| 命中火花 | `Scripts/Enemies/HitSpark.gd` |
| 料理台工作特效 | `Scripts/Kitchen/CookerWorkArt.gd` |
| 净化水花 | `Scripts/Kitchen/PlateSink.gd` |

地面装饰采用本地确定性计算，不消耗游戏随机数。新增动态装饰数量有限，但这一轮没有进行极端同屏压力测试，实际帧率仍应结合游玩观察。

## 验证与预览

已通过以下检查，无脚本解析或运行错误：

- `validate_kitchen_presentation.gd`：物品大小、组合台槽位和手持信息。
- `validate_dish_presentation.gd`：装盘、容器和物品搬运显示。
- `validate_health_bars.gd`：玩家、普通敌人和 BOSS 血条；基础攻击伤害。
- `validate_cooker_progress_view.gd`、`validate_cooker_process_rules.gd`：加工阶段、熟成度、焦糊和显示只读性。
- `validate_forage_ui.gd`：采集显示与选项。
- `validate_boss_combat_movement.gd`：四个 BOSS 移动、技能周期与位移下限。
- `validate_menu_release_and_settlement.gd`：菜单输入隔离、暂停和结算边界。
- `validate_second_night_events.gd`：第二批事件的交易及跨天结算。
- `smoke_facilities.gd`：全部设施共同运行 180 个物理帧。

血条测试主动清除测试场景赠送的力量祝福，保证固定的基础伤害断言不受测试资源影响。Godot 仍报告本机证书库读取失败；编辑器导入时还报告安装目录的设置文件无法保存，这些不是游戏脚本错误。

运行实际截图工具：

```powershell
godot --path . --rendering-method gl_compatibility --script res://tools/render_art_overhaul.gd
```

输出位于 `_artifact_work/art_overhaul/`：食材、敌人、设施、NPC、菜品、酒水总览，以及标题、准备、料理区、对话、加工、战斗、采集、洗盘和结算截图。截图工具为核对视觉会在临时场景摆放样本物品，退出后不写入游戏状态。

本轮保留第二批事件快速测试配置：沙灵伤害 150、额外初始食材、初始金币与祝福，以及前五天的短营业时长。

## 第二轮：软沙漠环境与敌人、设施

后续调整：敌人改为圆身、短肢、大脸和各自不同的神态，去掉长尖嘴、细节密集的甲壳和大张口腔。可碰撞石块改为有厚度的立石，仙人掌改为带深轮廓的厚实植株群；可穿过的装饰分别是浅色贴地碎石、扁平幼株。依据 solid 状态选择不同素材，不靠缩放或颜色区分。碰撞半径与布局保持原值。

维护入口：`tools/cohesive_enemy_art.py` 只生成敌人；`tools/generate_environment_art.py` 生成四种环境素材。环境 SVG 在 Godot 导入时生成纹理。

- 敌人素材改为按物种区分轮廓：兔、鸟、骆驼、甲虫、飞蛾、蝎子、沙虫、秃鹫和巨蜥不再共用同一张脸。
- 敌人与设施使用哑光平涂和清晰深轮廓，减少反复叠加渐变造成的 AI 生成感；料理区改用偏冷灰绿的砂岩地砖，与暖木设施形成明确层次。
- 战斗区按本局种子和天数稳定生成绿洲、石头、仙人掌、枯木和碎石。大石头、较大仙人掌有碰撞，小装饰可穿过；最终 Boss 区只保留视觉装饰，维持弱点攻击和移动空间。
- 绿洲附近提高非肉类产物敌人的出生倾向，但不改变敌人总数、掉落预算和区域归属；脆脆芽对应的耐旱敌人保持远离绿洲的例外规则。
- 环境装饰使用独立随机流，不消耗战斗随机数；采集点、入口、食材箱和主要路线会被避让。
- 运行时只创建少量静态碰撞体，不使用实时后处理或逐帧随机生成。
